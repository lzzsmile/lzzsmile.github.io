# 星愿花园 0.5.6 · 每一小步，都在向前

这是每日清单与陪伴互动的新版实现。主入口仍是 `/star-garden/`，PWA 身份、作用域和安装地址不变。仅修改本机工作区，未提交、推送或发布。

## 使用

- 「今天」固定显示本地当天的清单，不再前后翻日期；跨午夜自动换到新的一天。添加事项可选仅这一天、每天或周一至周五，从所选日期起生效。每件事每天完成一次。
- 点击圆形完成按钮，先保存一条记录和一步，再随机打开完整陪伴互动。一日可完成很多项、走很多步。连续打卡不会选择同一种互动。
- 六种互动为晨光滑块、击掌、浇水开花、纸飞机、拆开来信和三步小舞。每次打开/重温都从完整开场开始；关闭、刷新或未玩完都不会丢失已经保存的打卡。
- 「旅途」默认显示所选日期的一周（周一至周日）。在日历下方手柄下拉展开整月、上推收起，也可点「展开整月 / 收起为一周」；收起回到所选日期那一周。日期格保留正常页面滚动，滑动不会误选日期。左右箭头按当前周 / 月翻页，只浏览不改变所选日期；点击日历格选日期。日历不再提供月份跳转、直接日期输入或回到今天快捷入口。
- 有足迹的日期带浅绿底与深绿圆点，选中日显示深绿底和浅金圆点；今天有独立边框。读屏标签包含完整日期、今天标记和步数。键盘方向键、Home / End、PageUp / PageDown 移动焦点，Enter / 空格才选择日期。
- 点击日期可看当天记录，并在下方补记当时的清单或新增事项。未来日期不可选择或完成。撤销只移除选中的一次记录和它对应的一步；归档事项不删除已有足迹。周/月浏览与展开状态只在当前页面中保留，不改写记录、设置或备份。
- 「我的」是同行者设置入口，可定制默认人物或本机照片、称呼、衣服颜色与文案。未设置时，「今天」提醒前往「我的」；保存后，「今天」顶部卡片将同行形象、随机鼓励和用户原文案放在一起，仅供展示，不再提供卡片互动或编辑入口。默认人物也可直接保存为同行者。照片仅本机裁剪，支持 JPG/PNG/静态 WebP，最大 30 MiB；不上传。

设置「你的称呼」并保存后，三页页顶标题显示「xxx的星愿花园」，浏览器标签标题同步保留「旅途 / 我的」前缀；清空称呼后恢复「星愿花园」。陪伴者的名字仍只用于同行者，不作为花园标题。

## 首页的同行鼓励

- 内置 12 句鼓励，例如「一小步也很好，今天我们慢慢来」「不用赶路，照着自己的节奏往前走」。每次完整打开或刷新页面、从「旅途 / 我的」返回「今天」、浏览器后退回到「今天」，都随机选择一句。同一次页面运行中的相邻两次不会重复。
- 已停留在「今天」时，再点今天标签、保存打卡、其他标签同步、网络变化、日期更新或页面重绘，不会跳到另一句。关闭 / 后退关闭弹层也不会重新抽取。
- 切到后台少于 30 秒保留原句；离开至少 30 秒后回到前台才换一句。visibilitychange 与 pageshow 同时到达也只抽一次。若正在编辑或播放打卡互动，等弹层关闭再换，草稿与互动不受打断。停留首页跨午夜只更新当天清单，不换句。
- 首页卡片不再有「收下这份鼓励」按钮、回应或心形反馈动画；同行者形象、随机鼓励、原有自定义文案和进度保留。零步时不显示底部提示或空白进度栏，有足迹后仍显示步数和天数。
- 首页鼓励只在内存中记住本次打开的文案，不写入设置、记录、备份或新增持久存储，不增加步数。每次打卡仍保存后打开原有六种完整互动。
- 原有名字、衣服、照片与自定义文案保持不变；文案完整展示，不拿随机鼓励覆盖。未设置继续提供「去我的设置」。

## 页面精简

三页移除重复说明、宣传副标题与通用页脚；今天的保存说明、旅途空状态的长段说明、我的页尾文案均已去掉。日历保留日期格、足迹圆点、周/月前后翻页与展开收起，移除月份/日期跳转、回到今天的控件及处理事件。用户自己写的事项提醒、陪伴文案和记录备注不变；数据/备份、撤销/归档、权限/保存失败及照片格式提示保留。

## 更新提醒

新版下载完整后，「今天 / 旅途 / 我的」都会出现轻量提示，可选「立即更新」或「稍后」。稍后仅在本次打开期间收起提示；顶部「有更新」入口及「我的」标记仍保留，不需要专门翻到旅途。没有可用更新时不会显示这些提示。

不会突然弹窗或自动刷新正在使用的页面。编辑事项、同行者、照片或备份弹层打开时，不执行页面更新；从另一标签页更新也不会关闭本页草稿。保存中的操作同样不会被刷新打断。

如果本机预览还停在旧版，进入「我的 → 版本与离线 → 检查更新 → 更新并重新打开」。当前版本应显示 0.5.6；不需要清理网站数据、卸载 App 或换端口。

## 旧版数据与备份

同行者是否完成设置使用可选的 `settings.companionConfigured` 标记；新数据默认为未设置，明确保存设置后才变为已设置。没有该字段的旧备份仍可读取：已定制的名字、照片、衣服或文案继续视为已设置，原始默认值提示设置。旧版没有保存意图标记，因此无法分辨「从未设置」和「主动保存了完全相同的默认值」，这类记录可以在「我的」再保存一次；加载和取消都不会改写原记录。

新版使用独立的 `starwish-garden:growth:v2` 数据键。旧版 `starwish-garden:data:v1`、旧版导入前备份和最近删除区都不改写、不清理。

首次发现旧版时，只显示迁移入口，不会自动写入。推荐顺序：

1. 导出旧版 JSON，确认文件已保存到独立位置。
2. 查看迁移预览，再明确确认。
3. 旧打卡按一条一步迁入旅途；旧版完整原始对象保留在 `legacy.source`，原数据键也保留，并另留首次迁移原始快照。
4. 未完成习惯转为每日事项；已完成/归档事项保持归档。未完成单次事项放到迁移当天。旧愿望的目标次数、印章与待庆祝保留在只读档案，不再驱动新版每日清单。

常规新版 JSON 包含当前旅途、设置与迁入的完整旧档案。原始安全副本还包含本机旧版和恢复区的原始文本，损坏记录也能先导出留存。导入安全副本恢复其中的旅途主体，其他原始恢复区留在文件中，不自动覆盖本机恢复区。

恢复需要先预览确认。替换前保留一份导入前的旅途；这份恢复区只保留最近一次，请定期另行导出。JSON 包含照片与文案，未加密。存储不足、非法备份、过期预览和另一标签页修改都不会被当作成功保存。

保存需要浏览器提供 Web Locks，避免多个标签页互相覆盖。缺少该能力时保持只读，可查看和导出；请使用支持它的新版浏览器，在 HTTPS 或 localhost 打开。

## 本机运行

从仓库根目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

在同一台 Mac 打开 `http://127.0.0.1:4173/star-garden/`。这是本机预览，不是发布地址；它的数据与线上地址隔离。不能直接用 iPhone 的 localhost 访问 Mac，也不要用普通局域网 HTTP 代替正式 PWA/离线验证。

## 检查

从仓库根目录运行：

```sh
node scripts/build-star-garden-release.mjs
node scripts/build-star-garden-release.mjs --check
npm test
TZ=Asia/Shanghai npm test
TZ=America/New_York npm test
```

浏览器测试使用已有 Playwright 与 Chrome，不依赖或使用用户浏览器资料。若 Playwright 不在默认模块路径，用 `PLAYWRIGHT_MODULE` 指定其 `index.mjs`；可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定现有兼容浏览器。

```sh
node tests/star-garden-home-companion.browser.mjs
node tests/star-garden-growth.browser.mjs
node tests/star-garden-calendar.browser.mjs
node tests/star-garden-copy-cleanup.browser.mjs
node tests/star-garden-growth-scenes.browser.mjs
node tests/star-garden-growth-update.browser.mjs
```

最后一个测试需要本机 Git 存在历史提交 `d932be3`（实际旧版 0.4.2）；可用 `GARDEN_LEGACY_REF` 指定等价基准。它从旧版 worker 自身的资源清单加载历史文件。

0.4.x 的 `star-garden-focus/customization/experience/update.browser.mjs` 脚本是旧界面的历史回归，不代表 0.5 的界面验证。新版请运行上面的 growth 与 calendar 浏览器脚本。旧模型/裁剪/更新模块的 Node 回归仍纳入 `npm test`。

## 发布和限制

修改应用文件后，APP_VERSION 与 worker VERSION 必须一致，并重建完整性清单。新版离线资源全部校验通过才会接管；不完整更新保留旧版。不要卸载主屏幕 App 或清理网站数据来更新。

没有真实 iPhone Safari、主屏幕安装、系统照片选择器、VoiceOver 或实机内存验证。桌面 Chrome 的手机视口、触摸与离线模拟不能替代真机。首次离线需要至少一次成功缓存；浏览器清理网站数据、系统回收存储、无痕模式仍可能丢记录，备份不能省略。
