## 1.4.0：独立应用地址与安全迁移

- Days Matter：发布后访问 `https://lzzsmile.github.io/days-matter/`。
- 星愿花园：`https://lzzsmile.github.io/star-garden/`，本次没有修改它的文件、数据格式或缓存。
- `/` 和 `/index.html` 目前只有简短迁址提示，不自动跳转，也没有实现导航页。以后可以直接替换根 `index.html` 为导航页。
- Days Matter 的页面、脚本、图标、manifest、release.json 和 service worker 全在 `days-matter/`。新安装的 PWA 标识、启动网址和作用域都在这个目录；新应用不会拦截根网址或星愿花园。
- 日子仍按路径使用独立的 localStorage 键。旧键 `niannian.days.v1:/` 不删除，新键为 `niannian.days.v1:/days-matter/`。**加载页面不会自动写入或覆盖日子。**
- 在原来保存日子的同一浏览器打开新地址，点击「查看旧版记录」，核对预览并先下载原始备份，再「确认复制到新网址」。仅当新键不存在时允许复制；即使新键已有空列表或损坏内容，也不覆盖、不合并。
- 复制前会重新校验源和目标，并与普通保存共用跨窗口锁。旧记录保留原始字节，复制后两份数据不会同步。旧窗口请停止编辑；旧版原始备份仍可从「设置 → 数据与备份 → 查看旧版记录与备份」下载。
- 新地址已经使用过、源记录损坏、存储权限/空间不足或浏览器不支持安全跨窗口锁时，自动复制不会继续。先保存原始备份，再决定是否通过现有 JSON 导入流程恢复；普通 JSON 导入仍为显式替换，不是合并。
- Safari 与旧主屏幕 App 可能有不同存储空间。先在原浏览器或原主屏幕 App 导出备份，核对迁移成功后再添加新地址到主屏幕；不要先清除网站数据或卸载旧图标。未在实体 iPhone 验证迁移。

### 根 service worker 的收尾

根 `sw.js` 是旧 Days Matter worker 的退役脚本，更新后只注销自己，不注册新根 worker、不接管页面、不清理用户存储或任何缓存。**以后做根导航页时也请暂时保留这个文件。** 根提示页和新应用会请求已有根注册检查更新。离线老设备在重新联网更新前仍可能显示旧缓存页面，这是浏览器缓存行为，不是新站的兼容跳转。

根目录旧版 `app.js`、`calendar.js`、`updater.js`、`style.css`、`icons/` 和 `manifest.webmanifest` 暂时原样留存，让已经打开的旧页面可以完成备份；它们不是新应用入口，不再作为新版本的维护位置。旧根静态缓存也刻意不删除，以免破坏尚未迁移的离线页面。新应用只更新自己的 `/days-matter/` 缓存。

## 1.3.0：更多重复方式

- 支持不重复、每天、每周、每月、每年。所有重复都从原始日期开始，今天也是有效的一次；单次旧日期仍显示已过去天数。
- 每天按设备本地日历日计算，每周固定间隔 7 个日历日。农历日期先换算为起始公历日期，再按天/周推进。
- 每月按所选历法的同一天计算。公历 29/30/31 日遇到短月，默认取该月最后一天，也可以选择跳过；后续月份恢复原日数，不会逐月漂移。农历每月包括闰月，三十遇小月采用相同规则。
- 原有年度 2 月 29 日、闰月回退规则继续有效，仅对年度重复生效。原始年份和日期仍可编辑。
- 所有重复方式均导出未来 10 年的具体公历日期与逐次绝对 UTC 提醒，不使用会导致农历或月末错误的 RRULE。单次最多 20,000 条日历记录，超过时需减少选择并分批导出。日历导入后不会自动同步后续修改。
- 保持原本地存储键与 JSON v1 格式，旧备份可直接恢复；包含新重复方式的备份需要 1.3.0 或更新版本读取。未添加登录、上传或第三方依赖。

## 先了解安全与隐私

- 普通 GitHub Pages 部署是公开网页，知道链接的人可以打开。不要把网页误认为受账号密码保护的私人站点；公开仓库里的源码也公开。
- **把账号密码写进前端不安全。** 浏览器必须下载这些文件，别人可以查看代码、绕过密码判断；改成前端哈希或混淆也不能实现可靠访问控制。本包没有放入任何账号密码或假登录页面。
- 本应用不会把你的日子上传到服务器，没有云数据库、统计代码、第三方脚本或跨设备同步。GitHub 仍会处理普通网页访问请求；这不等于完全没有访问日志。
- 每位访问者通常看到自己浏览器里的记录，公开网页本身不会附带你的现有日子。本包没有包含个人备份。不要把备份 JSON、日历 ICS、密码或密钥上传到仓库。
- 本地记录与备份没有加密。同一浏览器配置中的其他使用者，以及同一来源下的其他网页脚本，可能访问记录。`https://同一用户名.github.io/项目A/` 和 `/项目B/` 同属一个来源；本包按路径区分存储和程序缓存以免误混，但这不是安全隔离。建议使用专用 GitHub 账号或专用域名，不要在同一来源部署不可信网页。
- 如果需要真正的账号登录、访问权限、多人隔离或云同步，需要另行设计服务器端认证和受控存储。纯静态 GitHub Pages 不能仅靠前端实现这些保护。

## 从现有私人站点迁移日子

更换网址不会自动搬走或删除旧数据，新的 GitHub Pages 网页首次打开为空是正常现象。

1. 在**原来保存日子的那个浏览器或主屏幕 App**里打开旧站点。
2. 设置 → 数据与备份 → 导出 JSON 备份。把文件保存到安全位置，别上传到公开仓库。
3. 在新 GitHub Pages 网页中，设置 → 数据与备份 → 选择刚才的 JSON 文件。
4. 核对预览数量。导入是**替换新站点当前全部日子，不是合并**；如新站点已有记录，先导出一份备份，再确认导入。
5. 检查日期原始年份、农历/闰月、多个特别关注与多条提醒。确认迁移成功前，保留旧站点、旧主屏幕图标和备份。

导入会保留原始年份、日期规则、备注、关注和提醒。旧版单条提醒会按原有规则转换，未设置提醒不会凭空新增。更换域名或 GitHub 用户名时，需再次用备份迁移。本次同一来源的根路径到 `/days-matter/` 迁移可用上方的专用流程；其他路径变化仍需备份迁移。Safari 和主屏幕 App 是否共享存储取决于 iOS 版本，安装后也请检查。

## 保留的功能

- 公历/农历日期，新增、编辑、删除、多个特别关注、搜索和筛选。
- 年度重复或单次日期；农历 1901–2100 年，闰月缺失、小月三十、公历闰日有明确选项。
- 原始日期显示“农历 · 八月十五”“农历 · 闰六月初一”“公历 · 12月18日”，年份保留在数据和编辑表单里。
- 每个日子可设置最多 10 条不同的提醒，默认不添加。
- 导出时明确选择日子与提醒；ICS 为未来 10 年的具体公历日期，农历不是错误的公历年度重复。
- JSON 读入、导出和文件选择统一限制为 24 MiB（25,165,824 个 UTF-8 字节），最多 1,000 个日子。浏览器本地存储配额可能更小；空间不足时保存或导入失败，原有记录保持不变。
- JSON 本地备份与恢复。数据不自动同步，不自动把任何日子写入仓库。
- 设置中的安装指引、日历导出、备份、版本和检查更新；首次成功联网缓存后可离线使用。

## 日历与离线限制

- 网页关闭时没有后台推送或闹钟。提醒需先导出 ICS，再由你手动导入系统日历。
- 提醒按**导出设备的时区**为每个具体日期计算，再写入 UTC 绝对触发时刻，避免跨夏令时的小时偏移。导出界面会显示当前时区；导入到其他时区或旅行后，提醒保持同一时刻，会显示为对应当地时间。夏令时跳过的时间按跳跃长度顺延（例如 02:30 → 03:30），重复时间采用第一次。未来时区规则改变时需重新导出。
- ICS 包含多条 VALARM，但不同日历客户端对多提醒、时间和重复导入的行为不同。实体 iPhone 上的导入兼容性尚未验证，关键提醒请导入后检查。
- 部分 iPhone 版本只预览 ICS 文件，需要在 Mac 日历导入后通过 iCloud 同步，或使用支持导入的日历应用。
- 日历导出是快照，不是订阅。以后修改或删除网页里的记录，不会同步修改已经导入的日历；重复导入可能产生重复。
- PWA 需要 HTTPS 或本机 localhost；不要双击 `index.html` 作为正式运行方式。首次加载或缓存安装失败时，离线不可用。系统清理缓存、清理网站数据、无痕浏览或存储配额也可能影响使用。
- 没有 iOS 开发者签名和 7 天签名到期，但托管服务、浏览器存储及系统缓存没有永久可用保证。

## 以后更新网页

修改网页代码后，建议用 Node.js 20 或更新版本运行：

```sh
node tools/bump-version.mjs 1.4.1
npm test
```

版本号必须比当前版本大。工具会同步更新 `days-matter/` 下的 HTML、release.json、service worker、资源版本地址与根 package.json；根 release.json 也会更新，让仍打开的旧标签页知道有新版本。根占位页和旧资源不再作为应用源文件更新。上传全部改变的文件到同一仓库、同一路径，等待 GitHub Pages 部署完成。

设置 → 检查更新 → 更新到新版本。更新不会清除日子，也不会在编辑中强制刷新。浏览器恢复前台会检查更新，但仍可能受平台/CDN发布延迟影响；稍后再检查即可。不要以清除网站数据、卸载主屏幕 App 的方式解决更新问题。

网页导出包不会自动接收原私人站点今后的修改。你需要自行把后续网页版本上传到 GitHub，或者另行请我准备新版文件。
